# Adding a city

A city needs no code of its own. What it needs is open data from its transit operator, one entry in the registry, and three files built from OpenStreetMap.

## What the operator has to publish

- **A GTFS feed**: the timetable as a ZIP archive at a stable `https` address. This is the only thing that is required.
- **GTFS-RT feeds**, any of the three: trip updates (delays and cancellations), vehicle positions, service alerts. The app leaves out what a city does not publish.
- **A licence** that lets the data be used and shown by anyone. Note its name and the page that states it; the app credits the operator in its settings.

Live data is matched to the timetable by `trip_id`, and within a trip by `stop_sequence` or, in feeds that give none, by `stop_id`. The GTFS-RT feeds must therefore describe the same version of the timetable as the GTFS feed. Delays may come as `delay` or as absolute `time`.

What the importer reads of the timetable: `routes.txt`, `stops.txt`, `trips.txt`, `stop_times.txt`, `calendar.txt` and `calendar_dates.txt` (either or both), and when present `shapes.txt`, `transfers.txt` and `frequencies.txt`. Stops without a time between two timed ones get theirs in equal steps. Everything else in the archive is ignored: fares, translations, stations as groups of platforms, a headsign that changes along the way.

The app refuses to follow a redirect to another server, so `gtfs.url` and the live feeds must be the addresses the files are really served from. If the operator asks clients to identify themselves or limits how often they may ask, check that against what the app does: it sends its name and repository as the `User-Agent`, fetches the timetable at most as often as the user chose, and fetches live data only while a screen shows it.

## 1. The registry entry

Add the city to `data/cities.json`:

```json
{
  "id": "example",
  "name": "Example City",
  "operator": "Example Transit",
  "timezone": "Europe/Warsaw",
  "center": { "lat": 50.0, "lon": 20.0 },
  "bounds": { "south": 49.8, "west": 19.7, "north": 50.2, "east": 20.3 },
  "gtfs": { "url": "https://transit.example/gtfs.zip" },
  "realtime": {
    "tripUpdates": "https://transit.example/trips.pb",
    "vehiclePositions": "https://transit.example/vehicles.pb",
    "alerts": "https://transit.example/alerts.pb"
  },
  "attribution": {
    "text": "Example Transit",
    "url": "https://transit.example/open-data",
    "license": "CC0-1.0",
    "apiDocs": "https://transit.example/developers"
  }
}
```

| Field | Meaning |
| --- | --- |
| `id` | Lower-case and unique; it names the city's files and its stored data, so it must never change |
| `name`, `operator` | Shown to the user as they are |
| `timezone` | The IANA name of the zone the timetable's times are in |
| `center` | Where the map opens |
| `bounds` | A box around everything the operator serves. A favourite place or the user's own location outside it is not offered in this city |
| `gtfs.url` | The timetable archive |
| `realtime` | Optional as a whole, and each feed in it on its own |
| `attribution` | Who to credit, the page that states the licence, the licence's name and, when there is one, the operator's documentation for developers |

Every address must use `https`.

## 2. Addresses, streets and the map

Address search, walks measured along streets and the map each need a file. All three are cut to the area of the stops in the city's GTFS feed, so nothing has to be drawn by hand. Addresses and streets come from an [OpenStreetMap extract](https://download.geofabrik.de/) that contains the city, the map from a [Protomaps basemap build](https://maps.protomaps.com/builds), of which only the tiles of the area are downloaded.

```sh
pip install osmium pmtiles
python tools/citypack/citypack.py example \
    --osm region-latest.osm.pbf \
    --map-source https://build.protomaps.com/<build>.pmtiles
```

This writes `data/addresses/example.tsv`, `data/walks/example.walk` and `data/maps/example.pmtiles`, which ship inside the app. Name them in the city's entry:

```json
"addresses": { "path": "addresses/example.tsv" },
"walks": { "path": "walks/example.walk" },
"map": { "path": "maps/example.pmtiles" }
```

A city without them still works: journeys are planned from stop to stop, walks are estimated from straight-line distance and there is no map. They can be added later, one at a time.

The files are derived from OpenStreetMap and may be distributed only under the Open Database License 1.0, with credit to OpenStreetMap contributors; the app shows that credit in its settings and on the map.

Two things are shared by all cities and rarely need touching:

- The map's styles, fonts and icons in `androidApp/src/main/assets/map/`, generated by `tools/mapstyle` (`npm install && npm run build`). Regenerate them only when the basemap version changes, or when a city's names need letters the shipped fonts lack.
- The short forms understood by address search ("al." for "aleja" and the like) in `AddressIndex`. A city in another language needs its own added there.

## 3. Check it

```sh
./gradlew build
```

The tests of `shared/provider` read the real registry: ids must be unique, addresses must use `https`, the centre must lie inside the bounds, and every file named must exist, with a map that covers the centre in enough detail.

To try the importer, the journey planner and the live-data parser against the city's real feeds, download them and pass their paths:

```sh
./gradlew :shared:gtfs:jvmTest :shared:routing:jvmTest -Pdojazd.gtfsZip=/path/to/gtfs.zip
./gradlew :shared:realtime:jvmTest -Pdojazd.gtfsRtDir=/path/to/folder/of/pb/files
```

Then run the app, choose the city and look at what a passenger would: lines grouped sensibly, a stop's departures, a journey across the city, the journey on the map, live delays.

## 4. Tell people

Add the city to the list of supported cities in the README, in the form of the others: the operator's website, its page about the data, and the licence.
